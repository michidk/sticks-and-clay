# Icon workflow research

Reviewed 2026-10-19. This audit covers the six public skills previously considered and Lucide's construction guidance. We read their instructions, supporting references, available scripts, evaluation descriptions and licenses. We did not execute their scripts or install their skills. Public examples demonstrate possibility, not a controlled comparison against this application's generator.

## Changes to this workflow

The previous defaults combined a universal 2-unit radius, primitive-first drawing and repeated instructions to remove detail. Those rules can suppress the exact blade edge, housing exit or proportion that identifies a tool. The earlier six-icon trial achieved consistent grid and colors and a 95/100 collection score, yet its chisel and measuring tape remained visually weak. That is evidence against using consistency or judge score as a proxy for taste, not proof that one instruction caused every bad result.

New prompts distinguish line, filled and duotone construction, scale radii to the part, allow optical deviations from the grid, and ask for identifying features and nearest lookalikes. Sharp functional edges and meaningful small details survive simplification. The builder studies three actual SVGs rather than relying entirely on verbal design advice. These examples are line construction lessons, not a mandate to turn colored artwork into Lucide icons.

Each new SVG review first makes a separate `svg-reader` call with only the current full-size, 64px and 24px PNGs and generic size instructions. It receives no asset name, brief, design, source markup, previous verdict or reference image. The judge receives that reading alongside measurements and compares it with the brief. Disagreement prompts a visible explanation or repair; it is not an exact-name gate. The reader can describe abstract marks and scenes. This is an independent invocation, not a human recognition study, and it may share model biases with the builder.

The reading adds one accounted text/vision call per SVG review round. Zero-round batches skip it. Existing saved judge checkpoints replay without a retroactive reader call; saved reader checkpoints resume normally. Individual acceptance stays human. The collection judge still checks family consistency and does not select the owner's favorite candidate.

## Pilot workflow using existing controls

For a new icon family, first request two or three candidates of one representative difficult subject. Keep the approved design fixed and vary one meaningful choice, such as the object's silhouette or angle. Compare them at the intended display size; the owner chooses the pilot. Use its SVG as the saved source for related variants or attach it as an SVG reference when generating the rest of the set. The generator receives both source markup and a rendered preview. Do not change the pilot's identity or geometry merely to accommodate an unrelated sibling.

This is a recommended use of existing controls, not an automatic pilot stage, new approval gate, or AI-selected winner. Large raster concept sheets, automatic tracing, new packaging targets and a separate candidate-selection UI are not introduced.

## Evaluation limits

Judge scores are diagnostic, not proof that the new output is prettier. Keep the original assets and compare actual renders at 24px and 64px. A useful evaluation freezes subjects, approved design, builder and review budget; records all calls and costs; and reports recognition and regressions per subject. An added reader changes the pipeline cost even when the number of review rounds is unchanged. A three-subject trial can reveal failures but cannot establish general quality or isolate the contribution of each prompt change.

## Local verification and trial

The full `bun run verify` gate passed: 270 tests passed, 115 integration/environment tests skipped, with TypeScript, web build and Eve typechecking successful. Five targeted integration cases also passed against an isolated migrated database, covering SVG publication, zero-review replay, legacy-review replay, saved-reader replay and collection replay. Saved SVG runs now retain their preview triplets for later revisions.

A fresh three-subject trial used the existing approved Fernwick design, `gpt-6-sol/high` builder, `gpt-6-astra/high` judge and two review rounds. Planning was rerun; palette values and compositions were not frozen between trials. These are known failure subjects used while designing the fix, not an unseen benchmark. The trial made 20 calls, estimated $0.76266, with no technical failures. Two additional same-evidence review calls cost $0.17455, for 22 calls and $0.93721 total. All six reader inputs were checked to contain only generic size instructions.

The visual result is mixed. The tape regained a colored housing, exposed blade and ticks compared with the previous solid block, but its short extension still reads ambiguously at 24px. The chisel has a longer blade and sharper end, yet its oversized handle and pinched connection remain weak. The paintbrush still has a heavy collar and a small enclosed tuft. The original icons retain advantages in some proportions and poses. This trial does not justify claiming that the new set is better overall.

The first reader detected ambiguous subjects, but the initial judge still approved the repaired chisel and tape at 91/100. That exposed repair-completion bias. The final judge prompt now prioritizes unresolved literal-subject recognition over completed repairs. Replaying the same inputs and images with that prompt rejected the chisel at 72 and tape at 76; no third generation was performed. The paintbrush's final review used the tightened prompt and ended with issues at 74. The collection review also flagged the tape's scale/weight inconsistency. The batch completed with issues. Historical individual verdicts were retained rather than overwritten by the separate audit calls.

The tightened rule is verified as better at rejecting these failures, not as producing better artwork. Because it changed during the trial, this is a debugging experiment rather than one uniform end-to-end benchmark of the final prompts. A chosen pilot or suitable source SVG remains necessary when an owner wants a specific visual standard. Local artifacts and complete run snapshots remain under `data/evaluations/icons-20261019/`; generated artwork and database state are excluded from Git.
